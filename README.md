# ライブ文字起こし

話した言葉をその場で文字にする Web アプリ(PWA)。iPad と Android で使う。
打ち合わせの議事録や、レッスン・稽古の指示を残す用途を想定している。

## 使い方

1. iPad は Safari、Android は Chrome で公開先の URL を開く
2. ホーム画面に追加する(iPad: 共有 →「ホーム画面に追加」/ Android: メニュー →「ホーム画面に追加」)
3. 記録の名前を入れて「● 開始」。初回はマイクの許可を求められる
4. 大事なところで「★ 印」。行はタップすればあとから直せる
5. 終わったら「■ 停止」→「書き出し」で、コピー・共有(メモ・メール・Dropbox など)・テキストファイル保存

- **要点リスト**: 話すそばから「決まったこと・指示」「やること」「保留・質問」「日時・数字」と、★ 印を付けたところを拾って並べる。
  AI は使わず、言い回し(「〜しましょう」「〜弾いてください」「〜までに」「〜ですか」など)を手がかりに端末の中で拾うので、
  料金も通信もかからない。項目の横の時間を押すと、その発言の行へ移る。iPad の横向きでは左右に並び、スマホ幅ではタブで切り替える
- **Claude で詳しく**: 文字起こしに「要点・決まったこと・やること・保留にまとめて」という頼み方を付けて Claude に渡す
  (共有から Claude アプリを選ぶか、コピーして claude.ai に貼る)。お使いの Claude のプランの範囲で使え、追加料金はかからない
- **取り込む**(左上 ☰ →「取り込む」): Google の「音声文字変換」など、ほかのアプリで文字にしたものを取り込んで記録にし、
  要点リストを作る。離れた声はこのアプリより音声文字変換のほうがよく拾うので、稽古・打ち合わせではこちらの使い方がおすすめ
  - 音声文字変換で文字を長押しして全部選び「コピー」→ このアプリの「貼り付け」→「取り込む」
  - ホーム画面に追加してあれば、音声文字変換などの「共有」からこのアプリを選んでも取り込める(テキストファイルも可)
  - 行頭に時刻(`[00:12]`・`午後3:21` など)があれば経過時間に直す。無ければ時間なしの行になる
  - 大事な行は、左の時間(時刻が無い行は「・」)を押すと ★ が付き、要点リストの「印を付けたところ」に入る
- **字幕**: 大きな文字で最新の数行だけ出す(聞こえの補助や、離れた所から読むとき)
- **記録の一覧**(左上 ☰): 過去の記録を開く・消す。記録はその端末の中だけに保存されるので、残したいものは書き出す
- 録音中は画面が消えないようにしている(画面が消えるとマイクも止まるため)

## 録音をあとで Mac で文字にする(高精度・無料)

稽古場では、スマホの録音アプリで録るだけにして、帰ってから Mac(M1 以降)の Whisper で文字にする。
離れた声にも強く、端末の音声認識より精度が高い。録音は Mac の中だけで処理し、外へは送らない。

**最初に1回だけ(Mac のターミナルで)**

```bash
git clone https://github.com/7188692jaakiko-a11y/live-transcribe ~/live-transcribe
```

(git が無いと言われたら、出てくる案内に従ってインストールしてから、もう一度実行する)

**使うとき**

1. スマホの録音を Dropbox などに入れておく
2. Finder で `~/live-transcribe/mac/文字起こし.command` をダブルクリック
   - 初回は「開発元を確認できない」と出ることがある。そのときは右クリック →「開く」→「開く」
   - 初回だけ、必要な部品と Whisper のモデル(約1.6GB)をダウンロードするので、数分〜十数分かかる
3. 出てきた画面で録音を選ぶ(複数選べる)
4. 終わると、録音と同じフォルダに「録音名_文字起こし.txt」ができて開く。中身は `[分:秒]` 付きの行
5. スマホのアプリで ☰ →「取り込む」→「テキストファイルを選ぶ」で取り込むと、経過時間付きの記録と要点リストになる

- 使うモデルは `mlx-community/whisper-large-v3-turbo`(Apple シリコン向けの Whisper)。話していない言葉を書かないよう、
  無音が続くところは飛ばし、同じ文の繰り返しは1つにまとめている
- 音声は Mac 付属の `afconvert` で読むので、ffmpeg は要らない(m4a・mp3・wav など)

## しくみ

- 文字への変換は、端末のブラウザに入っている音声認識(Web Speech API)を使う。料金はかからない
  - iPad の Safari は Apple の音声認識、Android の Chrome は Google の音声認識。どちらも多くの場合、音声は各社のサーバーに送られる
  - iPad では「Siri」と「音声入力(キーボード)」がオンになっている必要がある
- 無音などで認識が止まっても、「開始」を押している間は自動でつなぎ直す
- iPad の Safari は確定しないまま認識を終えることがあるので、途中の文字も確定として残す
- Android の Chrome が前の文を含んだ長い文をもう一度確定させることがあるので、その場合は前の行を置き換える

## 要点リストのしくみ

- `points.js` の言葉のリストに当てはめて拾う。上から「保留・質問」→「やること」→「決まったこと・指示」→「日時・数字」の順に当て、
  最初に当たったところに入れる。拾い方を変えたいときは、この言葉のリストを足し引きする
- 句点(。？！)があれば文ごとに、無ければ1行ごとに判断する
- ★ 印は、その直前の発言を拾う。印の行に書き足したメモは(かっこ)で添える
- 行頭に ★ が付いた行(左の時間を押して付けたもの)は、その行自体を印として拾う
- 言い回しで拾うだけなので、意味を読んでまとめるわけではない。きちんとした要約は「Claude で詳しく」を使う

## 分かっている弱点

- このアプリの「● 開始」(ブラウザの音声認識)は、端末の近くで話さないとほとんど反応しない(Android で確認)。
  離れた会話は「音声文字変換」で文字にして取り込むほうがよく拾う
- 音楽が鳴っている中の声は、端末の音声認識では取りこぼしが多い(レッスン中の演奏と重なる指示など)
- 話者の区別はできない
- アプリを裏に回すと(ほかのアプリに切り替えると)マイクが止まる

クラウドの高精度な音声認識や AI の要約を組み込めば改善できるが、使うたびに料金がかかるので採っていない
(使った分だけ料金のかかる仕組みは入れない方針)。

## 公開(GitHub Pages)

マイクを使うには https が必要。`main` に push すると `.github/workflows/pages.yml` で GitHub Pages に公開される。
リポジトリの Settings → Pages で Source を「GitHub Actions」にしておく。
無料のプランで Pages を使うにはリポジトリを公開(public)にする必要がある。
記録の中身はリポジトリには入らない(各端末に保存される)。

## 開発

```bash
python3 -m http.server 8799          # http://localhost:8799 で開く(localhost ならマイクが使える)
npm install
CHROME_PATH=/path/to/chrome npm test # 音声認識を偽物に差し替えて、表示・保存・書き出し・要点リスト・取り込みを確かめる
python3 -m unittest discover -s mac/tests   # Mac の文字起こし(Whisper と afconvert は偽物に差し替え)
```

ファイルを変えたら `sw.js` の `CACHE` の番号を上げる(端末に古い版が残らないように)。
